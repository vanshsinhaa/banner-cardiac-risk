# Trace review and correction (Taiga #75)

> Updated 2026-11-23: the editor was redesigned into the Review → Confirm → Risk
> score flow (`src/components/review/`). See
> [risk-score-and-review-ux.md](risk-score-and-review-ux.md) for the current
> interaction design; the storage and limits below still apply.

Story: Dr. Chen reviews and manually corrects the auto-detected waveform trace
before it is processed, so the signal feeding the risk score can be trusted.

## What it does

- Draws each lead's auto-detected trace (dashed grey) and the corrected trace
  (solid blue) over the de-identified EKG image. Other leads stay visible in faint
  green; clicking one selects it.
- Reviewers can **drag** a point, **add** a point by clicking on or near the
  selected trace, and **delete** a point by double-clicking it or selecting it
  and pressing Delete. Arrow keys nudge the selected point.
- **Reset lead** puts a lead back to the auto-detected trace. The reset is also
  logged.
- Every change is appended to an **edit log** with the lead, the kind of change,
  the point index, the before/after values (seconds, mV) and an ISO timestamp.
- **Save corrected trace** sends `POST /api/trace-corrections`. The record keeps
  `autoDetected` and `corrected` as separate full-length sample arrays, together
  with `editedLeads`, `edits` and the alignment that was used.

Entry points:
- In the capture result screen, a **Review detected trace** button appears once
  the digitizer returns leads.
- `/trace-review` is a demo that needs no services. It uses the synthetic page
  `public/synthetic-ecgs/standard-12-lead.png` and
  `src/lib/traceOverlay/fixtures/demo-digitization.json`, generated by
  `scripts/makeTraceReviewFixture.py` with deliberate errors in leads I
  (baseline drift), aVF (clipped R wave) and V2 (spike).

## Design

| Piece | File |
| --- | --- |
| mV/time ↔ image pixel mapping | `src/lib/traceOverlay/geometry.ts` |
| Control points, interpolation, applying corrections | `src/lib/traceOverlay/controlPoints.ts` |
| Review state and edit log (pure reducer) | `src/lib/traceOverlay/traceEdits.ts` |
| Save payload validation | `src/lib/traceOverlay/correctionPayload.ts` |
| Editor UI | `src/components/review/TraceEditor.tsx` (in `ReviewFlow.tsx`) |
| Save route | `src/app/api/trace-corrections/route.ts` |

- **Placement.** The digitizer returns mV samples (5000 per lead), not pixels.
  The overlay therefore places samples using the standard printed layout:
  10 s grid, 25 mm/s, 10 mm/mV, three rows of four 2.5 s leads and a lead II
  rhythm strip. Reviewers can line it up with per-lead shift/gain and grid
  position sliders.
- **Editing.** Reviewers edit control points: one every 40 samples, plus local
  peaks so narrow QRS complexes are kept.
- **Auto trace is never changed.** The auto-detected points are frozen. On save,
  the original digitizer samples are reused wherever an edit did not change the
  line, so untouched leads are stored byte-for-byte as the digitizer returned
  them.
- **Strict save payload.** The route rejects unknown fields, unknown leads,
  arrays of the wrong length and malformed edits. The capture id is restricted
  to `[A-Za-z0-9-]`. Only a summary (no trace values) is written to stdout.

## Known limits / follow-up

- **Approximate alignment.** Alignment comes from the layout, not from the
  digitizer. Follow-up: return the per-lead pixel polylines and the
  aligned-to-upload transform from `digitizer-service` (it already has
  `raw_lines` internally), then drop the sliders.
- **Plaintext storage.** Corrections are stored as plaintext JSON under
  `.data/trace-corrections/` (gitignored), because there is no database yet.
  Encrypted storage (#50) is still open.
- **Edit log not in the audit stream.** The log is not yet sent to the #61 audit
  stream (`faith/audit-events`, unmerged). That schema only accepts fixed fields,
  so the plan is to audit a `trace_correction_saved` event and keep the values in
  the correction record.
- **Corrected trace not used downstream.** Analysis does not consume the
  corrected trace yet. #72–#74 (T-wave metrics) should read `corrected` when it
  exists.
